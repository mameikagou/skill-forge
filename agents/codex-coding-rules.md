# Codex 写代码规则（用户 2026-10-16 定）

下面这些都是这台机器上 Codex 实际犯过的错，每一条都照做。

## 动手之前

1. **先找现成的，再写新的。** 动手写任何辅助功能前，先在仓库里搜一遍有没有现成的实现，比如交易日历、读数据表、均线、排名、远程调用、发消息、卡片格式。用 `rg "def 函数关键词"` 和 `rg "import 库名"` 搜。找到了就 import 来用；现成的不完全合适，就改它、给它加参数，不要另写一份。回复的第一段写清楚：搜了什么，复用了哪些函数，为什么还要写新的。
2. **改一个函数，先列出所有调用它的地方。** 用 `rg "函数名("` 找全，所有调用方一起改、一起测。不要只改被点名的那一处。
3. **用户的话以问号结尾，就是在提问。** 只回答问题，给事实和数据。不要顺手改代码、建分支、跑任务，也不要在末尾追加"要不要我现在开始做"。
4. **方案只给一个。** 不要拆成"稳妥版 / 激进版"，也不要写"先做个简单版，看看效果再说"。大改动可以分步执行，但每一步做完都要能用、能验证。
5. **给了网页链接，先把整页读完再动手。** 库的用法出错时，回去把文档重新读一遍，不要靠猜。

## 代码结构：高内聚、低耦合

6. **同一件事只放在一个地方。** 一类功能一个模块，一个功能一个函数，用参数区分不同情况。不要为每次实验、每个版本新建文件，比如 `*_v1.py`、`*_v2.py`、`*_extended.py`、`*_strict.py`、`*_review.py`、`*_audit.py`、`*_quality.py`。新建 `.py` 文件之前，先在回复里说明为什么不能放进现有模块。
7. **依赖只能单向。** 底层模块（读写数据、数据库、配置）不许 import 上层模块（业务计算、卡片、命令入口）。写在函数里面的延迟 import 也算。上层要用的东西，往下沉到底层；不要让底层反过来调上层。
8. **不许 import 实验代码。** 生产代码要用某个实验模块里的函数，就把这个函数挪进正式模块，再让两边都从正式模块 import。
9. **旧的和新的不并存。** 用新逻辑替换旧逻辑时，在同一个提交里删掉旧代码、兼容层和没人调用的函数。你写的代码你负责清理。

## 代码写法

10. **写人能读懂的 Python。**
    - 不写嵌套的三元表达式（`a if x else b if y else c`）。
    - 不写多层嵌套的推导式。
    - 业务数据不用单个字母做变量名，比如 `f`、`p`、`r`、`c`、`x`。
    - 一个函数只做一件事，大致控制在 50 行以内、参数不超过 6 个、嵌套不超过 3 层；超了就拆开。
11. **不要为了省事绕开依赖。** 需要哪个库就直接 import，不用 `try: import ... except ImportError` 包起来。成熟的文件格式（HTML、XML、JSON、CSV、YAML）用现成的库解析，不自己拿正则或字符串切分手写解析器。
12. **不要在命令里塞长脚本。** 不在 Bash 里写超长的多行命令。不把一段 Python 代码拼成字符串，再通过 `ssh ... python -`、`python -c` 或 `subprocess` 的 `input=` 传过去执行。要执行脚本，先写成文件。
13. **改代码只用编辑工具。** 不写 Python、sed、perl 脚本去批量改源码。
14. **出错怎么处理，分场景。**
    - **算账、回测、数据入库**：出错就当场报错停下。不编造价格，不把缺的值填成 0，不捕获异常后假装成功。
    - **每天的卡片和盘中监控**：某个次要来源失败了，比如一个新闻源、VIX、某一只股票补价，就隔离这一项，卡片照常发出，并在「查看来源」里写明缺了什么。不要因为一个字段对不上就整张卡拒绝发送。
    - 不加没有必要的校验。默认不用哈希和指纹，不写"和冻结值不一致就报错"。
15. **测试要真。** 不用 mock、假数据或特意绕过的写法让测试通过。功能写完要真的跑起来、测一遍、改到能用为止；不要写完就停，让用户去测。只跑和这次改动相关的测试。
16. **注释用中文，术语保留英文，少写。** 只写代码本身看不出来的原因，不复述代码在做什么。

## 不留改错痕迹

17. **只留最终正确的状态。** 改完代码、文档、卡片文案或 PR 描述，只写现在是什么样。不在注释、函数名、文档或 PR 里写"已删除 X""不再使用旧的 Y""无哈希""不含六配方票数"这类话。
    - 反例：用户让做番茄炒蛋，它加了东坡肉；用户问有必要加吗，它去掉了；可提交的 PR 标题写成"番茄炒蛋（无东坡肉）"，注释里还解释了一大段为什么不需要东坡肉。不要这样做。
18. **用户改过的文件，以用户改后的为准。** 每次修改前重新读一遍文件。用户删掉的内容，不要加回去。

## 操作安全

19. **不用 git 丢弃改动。** 不用 `git reset --hard`、`git checkout -- 文件`、`git restore`、`git clean` 撤销改动，别人的改动尤其不能动。用户说"回滚"，指的是用编辑工具把文件手动改回上一个状态。
20. **临时文件放进项目指定的临时目录**（analyze2quant 是 `/srv/qrant-runs/tmp`），不写进 `/tmp`。
21. **画图用 mermaid，不画 ASCII 字符图。**

## 说话

22. **写回复或文档前，先加载 `plain-talk` skill，并照它执行。** 用普通人看得懂的词，不用"落地""对齐""钉死""抓手"这类说法。不写"不是……而是……"，除非真有要对比的对象。不评论工作量大小。汇报第一句写结论和关键数字。
