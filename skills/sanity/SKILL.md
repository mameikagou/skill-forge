# 常识审查（质检协议）

先理解用户真正批准了什么，再用知识和证据审查。默认只读；用户明确要求实施时才写代码、拉数据或运行研究。

本 skill 回答"怎么发现不对"。凡属"研究时该怎么做对"的规则，唯一来源是 `mining-factors`；本文件只登记审查动作和状态标签。发现某条新审查规则其实是施工规则时，写去 mining-factors，不留在本文件。

## 审查服务于目标

**完整策略跑出来，费后效果更好，本身就是证据。** 先承认已有的业务改善，再用必要检查解释其可靠性与适用范围；不得因缺少额外检验、单因子显著性或完整归因而把改善说成“没有证据”，或追加开工门槛。

具体项目的股票池、参数、拟合方式和退出规则归该项目方案，不把一次策略的修改意见写成全局常识。

## 最高优先级：合同先于 skill

审查前先读取并整理：

1. 当前用户指令和最近一次业务决定。
2. 已冻结的 Grill 原始问答、PLAN、ROAD、研究合同和停止条件。
3. 仓库 `AGENTS.md`、当前 worktree、实际代码、数据合同和已有结果。

skill 只在合同没有规定的地方提供建议。不得用 skill 的默认偏好覆盖用户已经批准的预算、时间切分、候选类型、组合方式、机器学习授权、通过门或停止线。

特别禁止：

- 私自缩小或扩大用户批准的研究范围和预算。
- 把"建议先做简单对照"改写成"复杂方法永远不准用"。
- 把一个公式失败外推成整个因子家族、数据来源或研究方向失败。
- 把 `INCONCLUSIVE` 或 `DATA_BLOCKED` 计为研究失败。
- 在合同尚未满足停止条件时，因为 skill 偏好简单就提前结束。

若 PLAN、代码或执行状态偏离已冻结合同，先报告 `CONTRACT_CONFLICT` 并说明差异，随后按冻结合同处理；只有合同本身矛盾或缺少关键决定时才请求用户裁决。

本 skill 不规定"最多试几次""最多几个窗口""必须多少天完成"或固定统计阈值。数值预算属于具体项目合同。

## 先查知识，再评价点子

量化点子和市场判断默认先做资料检索，不能只凭模型常识或一次廉价回测判好坏。按任务需要依次查：

1. 项目内相关 planning、报告、失败账本、候选清单、代码和数据 inventory；优先用 `rg` 定向搜索。
2. 本地 `Brain` 知识库中的书、论文、文章和历史笔记。先找同一现象，再找最相近的旧因子和失败经验。
3. 可用的专业知识库 skill，例如 WorldQuant BRAIN 字段与 Alpha 资料；实际字段仍需回到项目数据合同验证。
4. 互联网中的原始论文、交易所或监管规则、官方文档和可靠研究资料。时效性可能变化或用户要求调研时必须联网核实。

记录来源、适用市场、样本年代、数据频率、结论和局限。论文或书中存在相似现象，不代表本项目一定有效；没有找到先例，也不等于点子必死。

点子依据可以来自：已有理论、书本或论文、市场制度、可靠实证异象、项目失败诊断、新数据，或者事前定义的数据搜索。经济故事不清楚会降低可信度，但不能在用户允许数据驱动搜索时被 skill 擅自设为否决条件。

### 评价知识依据和新增信息

结合检索结果回答：

- 这个现象在什么市场、时期和数据上被发现过。
- 它最接近项目里哪个旧因子，新增信息是什么。
- 可能的收益来源、失效状态和交易困难是什么。
- 资料里的结论能否合理迁移到当前 A 股、币圈、美股或 ETF 场景。
- 当前数据是否能按真实可见时间计算。

优先寻找与点子相反的研究和本项目失败记录。知识依据决定"值得怎样研究"，不能替代本地验证。

### 用书本反例约束结论，不封杀探索

书中或本项目已有反例时，必须写出候选与反例在市场、样本、持有期、股票池、规模、行业、状态和公式上的异同，再决定怎样分层检验。反例降低的是结论置信度，不是候选的研究资格。

例如，《因子投资：方法与实践》指出传统动量在 A 股整体较弱，小盘股还可能呈现反转。这意味着新的趋势或情绪候选要预先检查规模、行业和市场状态，说明它新增了什么；不能仅凭"它像动量"直接删除，也不能忽略反例把同一家族换名后当成全新信息。

这些分层用于查清适用条件和共同失效方式，不自动升级为硬通过门。不得要求弱因子在每个规模、行业、年份和状态中都独立有效；局部有效可以保留，但适用范围必须在看测试答案前定义。

## 选择审查模式

先声明当前是哪一种：

- `SINGLE_IDEA`：审查一个具体公式或策略规则。
- `FACTOR_CAMPAIGN`：审查一批候选、参数、组合或模型的研究流程。审查尺子以 `mining-factors` 各节为准（见下方索引）。
- `SYSTEM_AUDIT`：审查数据、研究、回测、模拟盘和实盘主线。

同一套结论不能跨层级滥用。单个公式失败只产生公式级结论；只有 campaign 按合同完成了足够广度和深度，才允许产生家族级结论。

## 默认裁决方向：宁可放过，不错杀

常识审查的职责是暴露风险、补齐问题和纠正评估方法，不是替研究流程提前淘汰候选。证据不足时，默认保留研究资格：标记 `KEEP_WEAK_SEED`、`SUPPORTED_FOR_RESEARCH`、`POSSIBLE_REDUNDANCY`、`EVALUATION_MISMATCH` 或 `INSUFFICIENT_EVIDENCE`，并说明下一步怎样验证；不得为了显得谨慎而直接写成失败。

只有已证实的致命问题才允许阻塞当前公式或实现。因子很弱、只在部分时期有效、经济解释暂时不清楚、与旧因子相关、一次回测为负或某项诊断不好，都不能单独构成淘汰理由。

拿不准候选是否重复、是否属于某个家族或应使用哪种评估方法时，举证责任在审查者：先保留，标明不确定性，再交给开发期的组合、去重和归因过程处理。不得要求候选自己证明"绝对不重复"后才准进入原料池。

## 把交易规则说清楚

审查具体信号时，先要求提案写清：

1. 交易哪个市场和哪些标的。
2. 在什么时刻，用当时已知的什么数据产生信号。
3. 最早什么时候下单，以什么价格口径成交。
4. 持有多久，什么条件卖出或换仓。
5. 希望改善哪段未来收益或哪类风险。

说不清时标记 `REWRITE`。不要替提案者补成另一套策略。

## 因子研究实质规则索引（本体在 mining-factors，此处只登记审查动作）

审查因子候选、组合或策略时，逐项对照 `mining-factors` 对应章节；违规按所列方向处理，规则内容以施工手册为准，本文件不得复述：

| 审查对象 | mining-factors 章节 | 审查动作与状态 |
|---|---|---|
| 信号用途与评估尺子是否匹配 | 信号用途与尺子对齐 | 不匹配标 `EVALUATION_MISMATCH`，换尺子再评价；不得据此宣布点子失败 |
| 弱因子是否被过早淘汰 | 弱因子保护与分层组合 | 发现单独盈利门、逐年盈利门或"先击败现役"资格赛即 `CONTRACT_CONFLICT` 或纠正评估 |
| 公式数是否被当成独立信息 | 挖真实信息，不是公式数量 | 报告缺三计数（公式/机制/有效维度）或同标签统计被重复计票时，要求补报 |
| 排序分数是否被当成幅度 | 排序是顺序，不是幅度 | 分数差换算收益、用于开仓/续持/Kelly：`FATAL_FLAW`（含义不成立级别） |
| 调仓是否有净增益门或排序纪律 | 增量成本与调仓门 | 只比单边费率、忽略最低佣金按笔计算、排序基线谎称逐笔证明净增益：要求重算 |
| 持有期是否被实现成到点强清 | 持有期有三种合同 | 复核间隔被写成强制清仓、为重置时钟卖出再买回：实现错误，修复后重跑 |
| 缺价是否失败关闭 | 成交价缺失必须失败关闭 | 查调用链价格回退；发现回退 `FATAL_FLAW`，冻结参数重放，工程修复不算调参 |
| 决定→订单是否一致 | 头寸状态机与零订单契约 | `HOLD`/`blocked` 产生订单、隐性等权重建、未成交重试伪装再平衡：`FATAL_FLAW`，重跑正式结果 |
| 动态股票池是否回填 today's 门槛 | 时点数据与动态股票池 | 用当前规模/成分/流动性门槛排除早期合法样本：要求按日重算并报告逐日可用数 |
| 逐币风险额度是否真隔离 | 带杠杆品种的单币风险额度 | 名义 10% 冒充亏损上限、共享现金兜底、影子账户截断：`FATAL_FLAW`，停在开发段 |
| 样本外纪律 | 样本外是策略的一部分 | 看过结果再调仍称样本外：改标"回溯时间验证"；重复访问的区间不得包装成未污染样本外 |

## 致命问题

以下已证实的问题可以直接否定当前公式或实现：

- 使用当时尚未公布的数据、今天的成分回填历史，或按不可能成交的价格交易。
- 信号出现时买不到或卖不掉，却按正常成交计算。
- 标签或股票池无法稳定复现。
- 信号只是在重复描述已经发生的收益，没有可检验的未来目标。
- 与已有因子实际相同，只改名字，没有新增数据或处理（`DUPLICATE_INFORMATION` 的定义见施工手册）。
- 看完测试答案后才改方向、窗口、股票池、成员或权重。
- 数据、日期、代码或公司行为映射错误，足以改变正式结果。
- 未经交易所官方 API 实查，把局部测试脚本中写死的变量（如临时 9 标的元组）误当成交易所全量标的池，擅自缩水研究范围或把执行通道局限倒打一耙当成因子缺陷。

标记 `FATAL_FLAW` 时，明确问题只属于哪个公式、实现或时间语义。除非存在适用于整个家族的共同致命矛盾，不得扩大结论。是否删除、改写或继续试验仍按项目合同决定，skill 不直接改 campaign 状态。

## Campaign 深度审计

结束或转向前必须核对：

1. 用户批准的研究范围和实际执行范围是否一致。
2. 批准预算与实际使用量分别是多少；未用完时是否已满足合同停止条件。
3. 测了多少真正不同的假说，多少只是窗口、归一化或参数变体（对照三计数报告）。
4. 失败结论属于公式、家族还是整个研究方向，证据是否支持这个层级。
5. 是否有微弱正向、但不够单独晋级的 `KEEP_WEAK_SEED`。
6. 是否把样本不足、数据缺失或评估方法不适配误写成失败。
7. 用户批准的组合与机器学习是否实际执行；未执行时不得声称 campaign 搜索充分。
8. 工程投入是否长期高于假说验证，是否在基础证据出现前过度建设。
9. 结果能否从数据版本、代码版本、配置和账本一条命令重跑。
10. 证据之间的共享标签、共享样本和重叠程度是否如实报告，有没有把多角度统计当多次独立验证。

最后只报告：合同要求的搜索和组合检查完成了多少、还缺什么证据、是否存在弱种子，以及合同中的停止条件是否已经满足。skill 不自行命令扩大或停止家族。

## 市场专用检查

### 涨跌停和事件

区分事件发生后可以观察到什么、下一步什么时候还能成交。不要把一字板收益、停牌收益或无法卖出的理论价格当成可实现收益。

### 美股到 A 股

写清美股信息发生时间、A 股最早可交易时间、业务关系和预计传导期限。对照美股大盘、美股行业和 A 股自身走势，但不要因为业务图历史短就把证据不足写成失败。

### 币圈尾部风险

区分平时风险排序和未来暴跌事件预测，使用当时真实存在、可交易的动态币池，并纳入手续费、滑点和资金费。单币风险额度的实质规则与回归测试要求见施工手册，此处按索引表核查引擎真实账户语义。

### ETF 轮动

将页面规则复现、严格时点研究和真实小资金执行分开。复现成功不代表策略有效，不同持仓与调仓合同不能混用。

## 反面教材：忽略目标和主线，沉迷细枝末节和工程安全

最危险的失败不是"代码不够安全"，而是安全地、严谨地执行了错的任务。当用户要一个结果时，不得把局部风险检查、对照实验、归因、哈希、新管理层或"更正规的架构"变成交付主体。这是审查科的常驻症状清单。

典型症状：

- 没有先用一句话复述用户真正要回答的问题和最终交付物。
- 已有权威主线可以直接完成任务，却又新建引擎、适配层、CLI、数据库、结果树、管理层或一次性脚本体系。
- 把本来只是证据维度的对照、消融、哈希、独立性、完整归因或工程门槛，擅自升级成必须先完成的目标。
- 大量时间用在让过程看起来完整，但没有产出用户要的策略、回测、数据、修复或结论。
- 工程安全手段改变了实验对象、缩小了用户批准的范围，或让研究在回答主问题前停止。

审查时按以下顺序核对被审对象：

1. 用户目标、交付物和已批准范围是否被写清。
2. 是否指定了现有唯一主线，它如何直接产生交付物。
3. 是否只保留了会改变结果真假的硬约束（未来数据、真实成交、费用、时间顺序、可重跑的最小证据）。
4. 是否选择了能最快直接回答目标的最小完整路径；额外对照、归因和基建是否越权成了前置目标。
5. 安全手段若改变目标、显著延迟主结果或需要新系统，是否先向用户说明了它防止的具体错误和成本。

ETF 因子组合案例（本清单的来源）：用户要"原四因子 ∪ 全部合法弱因子的联合策略费后结果"，执行方却拆成两套策略守擂、要求弱因子单独超额，并沉迷独立性与消融的完整性，始终没跑联合策略。正确做法按施工手册"弱因子保护与分层组合"节执行。

若被审对象无法直接回答目标，或当前工作不再推进该结果，标记 `CONTRACT_CONFLICT` 或 `SYSTEM_RISK`，建议停止扩大工程面、回到用户目标和唯一主线。

手续费和真实成交默认在组合层判断；不得仅因一个微弱因子单独交易覆盖不了最低佣金就否定它对低换手组合的增量价值（实质规则见施工手册）。防止海量搜索自欺，主要依靠完整试验账本、时间顺序正确的开发区、候选与组合规则冻结、以及只在冻结后打开测试验证期；不得用提高单因子门槛代替这些纪律。

## 正式研究和业务通过

按项目合同冻结数据、候选、方向、开发/测试区、成本、模型、组合、预算和停止条件。最终业务判断优先使用与真实账户一致的回测引擎、费用、整手、停牌、涨跌停、现金、容量和卖出阻塞。

候选在开发区的统计证据、组合价值和测试期的业务结果是不同阶段。完整策略费后改善是已运行范围内的正面证据；补充分析用于说明改善来源和可持续性，不抹掉已得到的结果，也不在便宜筛选阶段设置比最终业务合同更苛刻的隐藏门。

## 系统熵增与重构

独立检查：

1. 每类数据、配置、策略规则和运行状态是否只有一个权威来源（研究规则本身的权威来源是 mining-factors，不得有第三份抄本）。
2. 研究、回测、模拟盘和实盘是否调用同一份核心计算。
3. 历史结果能否定位到数据、代码、配置、候选和成交规则并重跑。
4. 新路径替代了什么旧路径；临时兼容层是否有调用方、删除条件和截止日期。
5. 是否为单轮研究新增数据库、CLI、产物树、正式模块或重复文件。

给出独立系统结论：

- `PASS`：权威来源唯一，结果可复现。
- `SIMPLIFY`：有可直接删除或合并的重复内容。
- `REFACTOR`：旧结构已妨碍正确性或研究效率，应先迁移主线并删除旧路径。
- `BLOCK`：数据时点、研究与执行一致性或结果追溯已经失真。

不要因为代码难看就整套重写。先用测试固定正确行为，指定新的唯一合同，迁移一条最小完整链路，再删除旧路径。

## 描述性审查状态

这些状态只描述证据，不替代用户和项目合同做执行决策：

- `CONTRACT_CONFLICT`：PLAN、代码或执行状态与已冻结合同冲突。
- `FATAL_FLAW`：当前具体公式或实现存在未来数据、不可成交、无法复现、决定被账户层改写等致命问题。
- `DUPLICATE_INFORMATION`：只是已有因子换名，没有新增信息（判定标准见施工手册）。
- `POSSIBLE_REDUNDANCY`：与已有信息相似，但尚未证明完全重复；保留进入开发期组合和归因，不得据此删除。
- `EVALUATION_MISMATCH`：候选用途与评估尺子不匹配，需换对方法后再判断，不能据此宣布点子失败。
- `REWRITE`：规则、标签、时间线或研究问题尚未说清。
- `SUPPORTED_FOR_RESEARCH`：知识或项目证据支持继续本地研究。
- `KEEP_WEAK_SEED`：有微弱新增信息，不能单独晋级，但可进入去重和组合研究。
- `INSUFFICIENT_EVIDENCE`：数据、样本或评估方法不足，不能判断。
- `NEGATIVE_EVIDENCE`：当前公式在已定义范围内得到负证据，但不得自动外推到整个家族。
- `SYSTEM_RISK`：系统主线、数据语义或可复现性存在风险。

## 默认输出

先给结论，再给：

1. 审查模式和冻结合同。
2. 知识与项目证据。
3. 当前公式、家族或系统真正存在的问题（按实质规则索引引用 mining-factors 章节名）。
4. 结论适用范围，明确不能外推到哪里。
5. 下一步研究或停止依据。
6. 实际读取的 planning、Brain、代码、数据和网络来源。

使用人话。专业词第一次出现时说明它量什么或做什么，不堆名词，不用漂亮收益代替逻辑。
